## Root cause of the perceived failure (benign startup race)
Container start order inside the pod: nginx comes up first and begins answering the startup probe, while uvicorn is still finishing its ~15s boot (Mongo index creation + idempotent admin/professional seeding). During that ~15s window nginx cannot reach the backend on 127.0.0.1:8001, so it logs `connect() failed (111: Connection refused)` and the K8s **startup probe** gets 503. **This is exactly what a startup probe is for** — it retries during boot and does not kill the pod. Once `Uvicorn running on 0.0.0.0:8001` / `Application startup complete` fired, `/health` returned 200, the startup probe went green, the container became Ready, health_check passed, and the run was promoted. The subsequent `GET /health 200`, `GET /api/public/professionals 200`, and `GET /api/auth/me 401` (expected unauthenticated) confirm the app is serving correctly.
